# Absorption map

For each routable document and each declared-gap stub, this map names the standard, specification or maintained project that could carry its load instead, which lane the document is in, and what would move it along. The repo's aim is to shrink toward the standards rather than grow beside them, so "none found" is a real and useful answer, and a document whose only contribution is a mapping the standards body has not made yet should retire once that mapping is accepted upstream.

This file is derived. Each document's frontmatter (`status`, `convergence`, `follows`, `replacement-by`) is canonical, and where this map disagrees with a document, the map is corrected to match it, which is why every lane below reads `none` except the one document whose frontmatter carries `follows:`. A candidate lane change is written into the Advance trigger cell and stays there until the document's own frontmatter changes.

Last verified sweep: none yet. The rows below are the initial fill of 2026-11-10, written from each document's frontmatter, text and Sources section, so the absorbers named here were not re-read against the documents for this pass and the Verified column records the fill date rather than a judgement sweep. The first quarterly sweep re-checks every row against its absorber; the weekly review runs only the consistency greps.

## Lanes and the four-bar test

- `none`: no absorber found, so the analysis is this repo's to keep.
- `follow`: an external canon carries the conceptual load for the document's slice; the document keeps its delta and stops growing there (`follows:` in its frontmatter).
- `retire-toward`: an absorber clears all four bars, and the document defers to it (`replacement-by:` and `status: RETIRING`).

The four bars are supported (a maintained project or a standards body with a release process), generally available (not a preview or draft), covers the substance (checked by reading the absorber against the document's claims, never by popularity), and citeable (a stable URL and version). One failed bar is enough to keep a candidate out of `retire-toward`, so for a `none` row the Bars cell names the bar the nearest candidate fails and why, rather than scoring all four.
